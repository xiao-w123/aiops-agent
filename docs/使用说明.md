# 使用说明

本文件说明如何运行、使用与演示本项目。

---

## 一、当前环境状态

你本机已经配置完成，**可以直接跳到第二节**：

| 项目 | 状态 |
| :--- | :--- |
| `.env`（API Key） | 已配置（OPENAI_API_KEY / OPENAI_API_BASE / OPENAI_MODEL） |
| `chroma_db`（向量库） | 已构建（5 个文件） |
| `venv`（虚拟环境） | 已就绪（Python 3.13.12） |

> 注意：以下所有命令都使用 `.\venv\Scripts\python.exe` 直接调用 venv 里的 Python，
> **不需要先 `activate`**。如果在 PowerShell 里直接敲 `python`，
> 用的可能是系统 Python 而不是 venv，会报"找不到模块"。

---

## 二、最快上手：先跑自检（不花 API 额度）

```powershell
.\venv\Scripts\python.exe selfcheck.py
```

预期输出末尾：`自检结果: 59 通过 / 0 失败`

**这一步永远应该先做。** 它不调用任何 LLM，约 30 秒完成，验证三件事：

1. 仿真环境返回的数据与测试集标注是否自洽
2. 测试集结构是否合法
3. 判分逻辑是否正确（含对抗性样例）

如果自检不过，说明环境有问题，此时不要去跑评测——跑了也是白花钱。

## 三、三种使用方式

### 方式 1：命令行单次提问（最省事）

```powershell
# 含 RAG 与证据校验
.\venv\Scripts\python.exe agent_v3.py

# 含 RAG，无证据校验（对比用）
.\venv\Scripts\python.exe agent_v2.py

# 无 RAG（对照组）
.\venv\Scripts\python.exe agent_v1.py
```

这三个脚本里内置了一个固定问题（"帮我看看 order-service 昨晚为什么响应变慢了"）。
**想换问题**，用编辑器打开对应文件，改这两行：

```python
QUESTION = "帮我看看 order-service 昨晚为什么响应变慢了"
```

`agent_v3.py` 还会额外打印是否触发了证据校验重答、以及校验耗时。

> 耗时参考：L1 类简单问题 2-4 秒；L3 类根因分析可达 **40 秒**，属正常现象
> （需要 5-8 轮 LLM 往返）。

### 方式 2：Web 界面（演示用）

```powershell
.\venv\Scripts\python.exe -m uvicorn main:app --reload
```

然后浏览器打开 **http://127.0.0.1:8000**

页面上有一个输入框，默认填好了示例问题，点"排查"即可。
停止服务按 `Ctrl + C`。

> **启动需要 30-45 秒**（要在启动时加载 embedding 模型），期间浏览器会连不上，
> 属正常现象，等它打印 `Application startup complete` 再刷新页面。
> 启动期间还有一个轻量探针可用：`http://127.0.0.1:8000/health`，
> 返回 `{"status":"ok","vectorstore":true}` 即表示就绪。

#### 多轮追问（支持）

Web 界面**支持多轮对话**。每轮回答下方会显示本轮调用了哪些工具、耗时多久、
以及已积累几轮对话。输入框旁的"清空"按钮可重置对话。

典型用法：

```
第 1 轮：order-service 昨晚的 CPU 使用率是多少？        （约 3 秒）
第 2 轮：继续，帮我定位根因                             （约 40 秒，会带上文）
```

第 2 轮 Agent 知道你在问 order-service，会直接拉取日志与发布记录做根因定位。
**若不支持多轮，第二问只会回复"请告诉我目标服务名称"**——这是验证多轮是否生效的判据。

> 为什么慢：多轮追问等同于一次完整的根因分析，需要 5-8 轮 LLM 往返。
> 实测第 2 轮约 39 秒，属正常。

#### 换问题

输入框是**可编辑的**，删掉里面的字、输入任何问题都可以，不需要改代码。

页面上还提供了一排**快捷链接**，点一下就会自动填入对应问题：

| 快捷链接 | 问题 | 实测耗时 |
| :--- | :--- | :--- |
| CPU 使用率（默认） | order-service 昨晚的 CPU 使用率是多少？ | 2.7 s |
| 发布记录 | order-service 昨晚发过版吗？ | ~2 s |
| 历史故障 | 历史上有没有类似的连接池故障？当时是怎么解决的？ | 3.5 s |
| 健康检查 | gateway-service 现在运行正常吗？ | ~4 s |
| 根因分析（较慢） | order-service 昨晚为什么响应变慢？ | 可达 40 s |

**要改默认填入的问题**，编辑 `index.html` 中 `<input id="message">` 的 `value` 属性：

```html
<input id="message" type="text"
       placeholder="例如：历史上有没有类似的连接池故障？"
       value="order-service 昨晚的 CPU 使用率是多少？">
```

**要改快捷链接**，编辑 `index.html` 里 `fill('...')` 中的文字。

> **演示提醒**：
> - 默认问题已刻意选为**最快**的一类（约 3 秒），避免开场冷场。
> - 推荐的演示流程：先点"CPU 使用率"（3 秒出结果，建立信任），
>   再追问"继续，帮我定位根因"（40 秒，展示完整根因分析能力）。
> - **避免一上来就点"根因分析"**——单次可达 40 秒。

### 方式 3：评测（出数据用）
```powershell
# 最常用：完整消融实验，基线与本方案各跑 3 次
.\venv\Scripts\python.exe eval_v3.py --configs both --repeats 3 --warmup 1 --workers 8

# 只跑基线
.\venv\Scripts\python.exe eval_v3.py --configs basic --repeats 3

# 只跑某一层（快速看效果）
.\venv\Scripts\python.exe eval_v3.py --configs both --level L3,L5 --repeats 2

# 极小样本验证链路（第一次跑建议先这样，避免一上来就大量调用）
.\venv\Scripts\python.exe eval_v3.py --configs both --limit 4 --repeats 1 --warmup 0

# 冒烟测试：6 条用例覆盖四个工具 + 拒答
.\venv\Scripts\python.exe eval.py
```

**耗时警告**：30 用例 × 2 配置 × 3 重复 = 180 次会话。复杂用例单次可达 40 秒，
`--workers 8` 并发下约需 **10-20 分钟**，串行则要 1.5-2 小时。
所以**务必带 `--workers`**，并且不要用 `--quiet` 配合管道重定向（会看不到进度）。

参数说明：

| 参数 | 作用 | 建议值 |
| :--- | :--- | :--- |
| `--configs` | `basic` / `verified` / `both` | 出数据用 `both` |
| `--repeats` | 每个用例重复次数 | `3`（少于 3 次标准差没意义） |
| `--warmup` | 预热次数，不计入统计 | `1`（摊掉模型冷启动） |
| `--workers` | 并发线程数 | `8` |
| `--limit` | 只跑前 N 条 | 调试用 `4` |
| `--level` | 只跑指定层级 | `L3,L5` |
| `--k` | RAG 检索返回条数 | 默认 `2` |

## 四、结果文件在哪、怎么看

每次评测都会在 `results/` 下生成：

| 文件 | 内容 | 用途 |
| :--- | :--- | :--- |
| `report_latest.md` | 分层指标表 + 消融对比表 | **论文直接引用这个** |
| `report_<时间戳>.md` | 同上，按时间留存 | 保留历史 |
| `diagnostics.md` | 逐条用例的工具调用序列 + 回答摘要 | **指标异常时排查用** |
| `raw_<时间戳>.json` | 全部明细（结构化） | 自己写脚本做统计检验 |
| `raw_<时间戳>.csv` | 同上，表格形式 | 用 Excel 打开看 |

**看到数字不对时，先看 `diagnostics.md`。** 它会显示每条用例实际调了哪些工具、
回答的开头是什么。判断"是 Agent 答错了，还是标注有问题"，全凭这个文件。

## 五、常见问题

### 提示 `ModuleNotFoundError`

说明用错了 Python。**必须用 `.\venv\Scripts\python.exe`**，不要直接敲 `python`。

### 提示 API Key 相关错误 / 401 / 余额不足

检查 `.env` 文件：

```
OPENAI_API_KEY=你的DeepSeekKey
OPENAI_API_BASE=https://api.deepseek.com/v1
OPENAI_MODEL=deepseek-chat
```

### 首次运行卡在下载模型

`BAAI/bge-small-zh-v1.5` 首次使用需下载（约 100MB）。
如果卡住或报 SSL 错误，先设镜像（`main.py` 和 `agent_core.py` 里已内置设置，
但 `rag_setup.py` 需手动设）：

```powershell
$env:HF_ENDPOINT = "https://hf-mirror.com"
.\venv\Scripts\python.exe rag_setup.py
```

### 想重建知识库

改了 `knowledge/` 下的故障报告后，需要重建向量库：

```powershell
.\venv\Scripts\python.exe rag_setup.py
```

### 中文显示乱码

PowerShell 控制台编码问题，加一行即可：

```powershell
$env:PYTHONIOENCODING = "utf-8"
```

（数据本身没问题，文件也都是 UTF-8。）

### 某些问题特别慢

正常。复杂问题（L3 根因定位）需要多轮工具调用 + 证据校验 + 可能重答，
单次可达 40 秒。L1 类简单查询只要 2-4 秒。

### 评测跑完 `exit code: 1` 是怎么回事

这是 PowerShell 管道 `Select-Object` 的正常行为，**不是程序报错**。
看输出末尾是否有"评测汇总"即可确认成功。

## 六、在别人电脑上从零跑起来

如果要在答辩电脑或新机器上部署：

```powershell
# 1. 进入项目目录
cd <项目路径>

# 2. 创建虚拟环境
python -m venv venv

# 3. 安装依赖（国内加速）
.\venv\Scripts\python.exe -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 4. 配置 API Key（新建 .env 文件，内容见上文）

# 5. 设 HuggingFace 镜像（国内网络建议）
$env:HF_ENDPOINT = "https://hf-mirror.com"

# 6. 构建知识库
.\venv\Scripts\python.exe rag_setup.py

# 7. 自检
.\venv\Scripts\python.exe selfcheck.py

# 8. 启动 Web 服务
.\venv\Scripts\python.exe -m uvicorn main:app --reload
```

> `chroma_db/` 已加入 `.gitignore`，所以 clone 之后**必须重跑第 6 步**，
> 否则 RAG 检索会失败。

## 七、各文件职责速查

| 文件 | 作用 | 需要改吗 |
| :--- | :--- | :--- |
| `simulator.py` | 仿真运维环境（**改数据来这里**） | 要加故障场景时改 |
| `testset.json` | 分层测试集（**改题目/标准答案来这里**） | 要加用例时改 |
| `evalframework.py` | 指标与判分逻辑 | 一般不动 |
| `agent_core.py` | Agent 构造与提示词 | 要调提示词时改 |
| `eval_v3.py` | 评测入口 | 不用改，用参数控制 |
| `selfcheck.py` | 自检 | 加了新规则后同步加断言 |
| `main.py` | Web 后端 | 不用改 |
| `index.html` | Web 前端 | 想改界面时改 |
| `rag_setup.py` | 建向量库 | 改了 `knowledge/` 后要重跑 |

**最常改的两个文件是 `simulator.py` 和 `testset.json`**——前者定义"环境里有什么"，
后者定义"问什么、标准答案是什么"。改完这两个，**务必跑一遍 `selfcheck.py`**
确认两者仍然自洽（自检的第一、二部分就是在查这个）。
